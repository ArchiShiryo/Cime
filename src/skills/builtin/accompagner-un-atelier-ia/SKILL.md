# Introduction to AI workshop

## Typical progression (2 h)

1. **Understand (15 min)**: AI produces probable text, not truth; it can be wrong and make things up. Demonstration with a question whose answer can be verified.
2. **Asking well (20 min)**: context, goal, constraints, expected format, example. Participants rewrite a vague instruction into a precise one.
3. **Create a small application (45 min)**: each pair describes a concrete need from their classroom, generates a first version in Cimes, tries it out, asks for two improvements.
4. **Check and protect (20 min)**: reread what the AI produced, test edge cases, never enter student data into an external service (`donnees-eleves-rgpd`).
5. **Share (20 min)**: each pair presents, discussion on uses and limitations.

## Facilitation stance

- Alternate short explanation and hands-on practice; never more than 10 minutes without practice.
- Plan a fallback if the network goes down (ready-made examples, `application-hors-ligne`).
- Encourage critical thinking: an AI response is a draft to be checked.

The detailed structure of a session plan is described in `atelier-pedagogique`.
