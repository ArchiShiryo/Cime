# Documenter une application

## README.md (en français)

1. **À quoi ça sert** en deux phrases.
2. **Pour qui** et dans quel contexte (classe, atelier, équipe).
3. **Comment l'utiliser** : étapes numérotées avec des captures ou exemples ; une action par étape.
4. **Où sont mes données** et comment les sauvegarder / restaurer.
5. **Problèmes fréquents** : question → réponse en une ligne.
6. **Pour les curieux** : comment lancer le projet (`npm install`, `npm run dev`), organisation des dossiers, où modifier les textes et les couleurs.

## Aide intégrée

- Un bouton « Aide » ou « Comment ça marche ? » ouvrant une page de trois à cinq conseils.
- Messages d'état explicites (« Enregistré à 14 h 32 »).

## Règles

- Écrire pour quelqu'un qui n'a jamais ouvert un terminal ; expliquer chaque mot technique.
- Ne documenter que ce qui existe ; relire l'application avant d'écrire.
- Indiquer la version et la date de dernière mise à jour.
