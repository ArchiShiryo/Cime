# Documenting an application

## README.md (written in French)

1. **"À quoi ça sert"** ("What it's for") in two sentences.
2. **"Pour qui"** ("Who it's for") and in what context (class, workshop, team).
3. **"Comment l'utiliser"** ("How to use it"): numbered steps with screenshots or examples; one action per step.
4. **"Où sont mes données"** ("Where is my data") and how to back it up / restore it.
5. **"Problèmes fréquents"** ("Common problems"): question → one-line answer.
6. **"Pour les curieux"** ("For the curious"): how to run the project (`npm install`, `npm run dev`), folder layout, where to edit the texts and colours.

## Built-in help

- An "Aide" ("Help") or "Comment ça marche ?" ("How does it work?") button opening a page with three to five tips.
- Explicit status messages ("Enregistré à 14 h 32" — "Saved at 14:32").

## Rules

- Write for someone who has never opened a terminal; explain every technical word.
- Only document what actually exists; read through the application again before writing.
- State the version and the date of the last update.
